# Product page

Operate. The shopper configures a product, reads the price that results, and orders. Form: configuration sheet.

- Top: a square photo plate (hairline, 4px corners, max 28rem, 20rem on phones) on the start side, thumbnails as a horizontal strip below when there is more than one image. The order sheet sits on the end side: name, brand and code, short line, one ruled row per option, a live price line, then quantity, one buy button and a square wishlist button.
- Option rows are label and value on a hairline. The selected value is named in the label. Only the active option uses the tenant accent. Swatches and option buttons are at least 44px on phones.
- Below: a section index (description, specs, reviews, related) that is sticky on desktop and tracks the section in view. Sections are a label column plus content, separated by hairlines. They are not tabs.
- Specs are a definition table built only from real data: brand, category, code, every variant attribute with its values, and tags. The section is omitted when there is nothing to list.
- Related items are the same-category products from the store, up to four, shown with the shared product card flattened to the sheet's hairline language (no lift, no peek pill, quiet badge).
- Phones: a bottom buy bar with the live price and one button appears once the in-page buy button leaves the screen and steps away when the footer arrives. It proxies the in-page button, so cart behavior has one source.
- One sale signal: struck compare price and a percent only when the catalog computed one. No icon trust chips, no kickers, no fabricated shipping or warranty claims.
- Empty gallery is a quiet field with a label.
